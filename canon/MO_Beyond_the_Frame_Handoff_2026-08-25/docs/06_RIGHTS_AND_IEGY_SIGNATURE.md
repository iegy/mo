## Important legal reality

A broad concept such as “an interactive comic that moves with scroll” cannot be made impossible to imitate through code. Protection is strongest around the specific expression of the project:
- Mo character design;
- PIX design;
- story scripts;
- worldbuilding;
- artwork;
- logos/names where protectable;
- original code;
- audio;
- exact scene design;
- source assets and production history.

For serious commercial protection, consider appropriate copyright/trademark registration in the relevant jurisdiction(s). This package is not legal advice.

## IEgy Signature system

Use multiple layers of provenance rather than one removable watermark.

### Project ID
`MO-IEGY-01`

### Chapter 01 signature
`MH-4047`

### Code source headers
Core files should include authorship metadata such as:
- Project: MO — Beyond the Frame
- Creator: Mohamed Hussein
- Website: https://iegy.net
- Project ID: MO-IEGY-01
- Version/build id

### Metadata
Add author/creator/copyright/application name, OpenGraph, structured data/JSON-LD, canonical site metadata where relevant.

### Internal namespaces
Names such as:
- `IEgySignature`
- `MoStoryEngine`
- `FrameBreakTransition`
- `MarginPortal`

These are not protection by themselves but help establish provenance when copied verbatim.

### Hidden signature elements
Examples:
- HTML comments;
- `data-*` markers;
- CSS custom properties;
- structured build metadata.

Do not depend on only one hidden marker.

### Visual/world signatures
Hide small creator marks naturally inside the world:
- `MH`
- `MH-4047`
- `IEGY-01`
- Broken Corner Mark

Examples: machine serial numbers, station signage, graffiti, model codes, documents.

### Asset metadata
Keep master/source assets with creator/project/copyright metadata when the format supports it.

### Git history
Use Git from the beginning of actual production. Commit:
- Story Bible;
- character references;
- scripts;
- prototypes;
- art assets;
- code.

### Release archives and hashes
For major versions create tagged archives, e.g.:
`MO-Chapter-01-v1.0`

Maintain hashes for important source/release files.

## Build version suggestion
Example:
`MO-1.0.0-IEGY`

Include commit hash and timestamp in build metadata when practical.
